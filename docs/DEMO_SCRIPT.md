# BriefBridge — 90-second demo guide

The challenge requires a short browser demonstration with the entrant personally explaining the project. Keep the final video under two minutes and use your own voice.

## Suggested narration

**0:00–0:15 — The problem**

"Project work often starts with a vague message: someone has an idea, but the goal, audience, deliverables and expectations are not clear. That creates rework before the real work even begins."

**0:15–0:30 — The product**

"BriefBridge is a project-intake workspace. I can capture the details manually, or use its agent network to clarify a rough request and turn it into a structured brief."

**0:30–0:55 — The agent workflow**

"Here I am asking BriefBridge to help plan a small business website redesign. The coordinator reads the current workspace, delegates scope analysis to the brief specialist, and asks for missing details rather than inventing them."

**0:55–1:15 — Review and save**

"The result separates the objective, audience, deliverables, constraints, assumptions and open questions. When I ask it to save, the browser shows me the brief and asks for confirmation. I can then export it as Markdown or JSON."

**1:15–1:30 — Open agentic web and Otari**

"The network is published as a public JSON manifest and network definition. It runs in the browser using the Open Agentic Web runtime, and Mozilla Otari routes model requests using the visitor's own key. Other agentic websites can discover and call the network without receiving my local saved briefs."

## Recording checklist

- Show the site running in a normal browser.
- Show AI model settings with the provider selected, but never show or reveal the API key.
- Demonstrate one clarification flow, one structured brief and the confirmation before saving.
- Show the public `agent-manifest.json` and network JSON in a browser tab.
- Explain the project yourself; do not use an AI-generated narration.
- Upload the video publicly to YouTube and add the link to the Devpost submission.
